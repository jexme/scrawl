# Порт на Windows

Статус: **не работает**, но собирается. `GOOS=windows CGO_ENABLED=0 go build ./cmd/scrawl`
даёт `scrawl.exe`, CI следит, чтобы так и оставалось (задача `windows-build`). Запуск
на Windows проверить нечем: ни одной строки здесь не запускали, всё ниже это проект, а не отчёт.

`scrawl.exe` сегодня умеет открыть окно настроек (`scrawl.exe -settings`: Gio работает на
Windows без cgo; кнопки portal, gsettings и значок в трее на Windows отвечают ошибкой). Остальное
говорит «захват экрана пока есть только в Linux» и выходит.

## Что уже переносимо

- Аннотации, рисование, склейка, формат файла, настройки, язык, клавиши: Gio и стандартная библиотека.
- Папки: `os.UserConfigDir()` это `%AppData%`, `os.UserCacheDir()` это `%LocalAppData%`,
  `~/Pictures/Screenshots` существует и на Windows.
- Заглушки под не-Linux: `singleton_other.go`, `clipboard_other.go`, `pwcapture/capture_other.go`,
  `screencast/dup_other.go`.

## Что нужно написать

Порядок по пользе: сначала то, без чего снимок не сделать.

1. **Захват.** `EnumDisplayMonitors` даёт прямоугольники мониторов, `GetDC(NULL)` и
   `BitBlt(..., SRCCOPY|CAPTUREBLT)` копируют экран, `GetDIBits` отдаёт пиксели. Процесс
   объявляется DPI-aware (`SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`), иначе координаты
   и размеры на мониторах с масштабом врут. Результат тот же, что у Linux: `[]screencast.Frame`
   (`Img`, `X`, `Y`). Если GDI не отдаёт часть содержимого (игры в эксклюзивном полноэкранном режиме,
   защищённое видео), запасной путь это Desktop Duplication API (DXGI) или Windows.Graphics.Capture.
   Для чистоты захват стоит спрятать за интерфейсом: сейчас `cmd/scrawl/main.go` напрямую вызывает
   portal, поэтому его кусок «получить кадры» надо вынести в `capture_linux.go` и `capture_windows.go`.
2. **Оверлей на нужном мониторе.** Патч Gio `third_party/gio.patch` делает `app.FullscreenAt` для
   Wayland; на Windows опция принимается, но монитор не выбирает. Нужна правка `app/os_windows.go`:
   безрамочное окно (`WS_POPUP`) с `SetWindowPos` на прямоугольник монитора и поверх остальных.
   Патч разрастётся, его удобнее держать форком или апстрим-запросом.
3. **Буфер обмена.** `OpenClipboard`, `EmptyClipboard`, `SetClipboardData`: `CF_DIBV5` для обычных
   программ и зарегистрированный формат `"PNG"`, чтобы мессенджеры вставляли без потерь. Для «отдельных
   файлов» нужен `CF_HDROP` со структурой `DROPFILES`. Ложится в `clipboard_windows.go`.
4. **Горячая клавиша.** `RegisterHotKey` требует цикла сообщений, значит нужен живой процесс: это
   режим `-tray`. На Windows значок и клавиша живут в одном процессе (`Shell_NotifyIcon` и скрытое окно).
   Поле «Горячая клавиша» в настройках на Windows пишет в реестр или в файл настроек, а не в gsettings.
5. **Один экземпляр.** Именованный мьютекс `CreateMutex("Local\\scrawl")` вместо `flock`.
6. **Автозапуск.** Ключ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` вместо `.desktop`.
7. **Уведомления.** Всплывающая подсказка у значка в трее (`NIF_INFO`) или WinRT-тосты; `notify-send`
   на Windows нет.
8. **Разрешения и выбор мониторов.** Кнопки «Выдать разрешение» и «Выбрать мониторы заново» на
   Windows не нужны: их надо скрыть, а не показывать с ошибкой.

## Выпуск

CI собирает `scrawl.exe` кросс-компиляцией без cgo. Для релиза нужен zip с `scrawl.exe`, лицензиями и README;
подпись кода и установщик (MSI или портативная папка) решаются отдельно.

## Как проверять

Нужна машина или виртуалка с Windows 10/11 и двумя мониторами разного масштаба (DPI 100% и 150%):
на них ломаются координаты. Без неё можно написать код и проверить, что он собирается, но не что
он работает, поэтому каждый пункт выше надо принимать только после живого запуска.
